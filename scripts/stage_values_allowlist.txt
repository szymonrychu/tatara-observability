# Closed-set label VALUE allowlist for scripts/check_metric_provenance.py.
#
# metrics_allowlist.txt validates metric NAMES only. A rule can select a metric
# that IS emitted while filtering on a label value that is NOT a member of the
# contract's closed set - the series never appears, and because every alert file
# sets default_no_data_state: "OK" the rule reports OK forever. Same failure class
# as a dead metric name, one level down (fix V7-7: this is exactly how a v6-era
# rule shipped a reference to the retired "pod-not-ready" stageReason and would
# have passed a name-only provenance check).
#
# 2026-08-08 (#97) - THIS FILE DID NOT CATCH THE stage -> state RENAME, AND THAT
# IS WHY THE state/stateReason/parkReason SECTIONS BELOW EXIST. tatara-operator
# v2.0.0 (#521) replaced the 16-stage machine with 8 states plus an orthogonal
# park flag, renaming the labels stage -> state and stageReason -> stateReason
# (terminal) / parkReason (park). The sweep only knew about the OLD four label
# names, so every rule re-pointed onto the new ones would have shipped with NO
# closed-set guard at all - re-opening the exact hole this file was written to
# close, one rename later. The label list is now driven by _LABEL_VALUE in
# scripts/check_metric_provenance.py; adding a section here without adding the
# label there is a no-op, and there is a self-test asserting the two agree.
#
# Sections below are `## <label name>` followed by one value per line, optionally
# `## <label name>:exempt-metrics` naming metrics on which that label means
# something else entirely. Regenerate against tatara-operator's own source of
# truth - internal/stage/stage.go (the Reasons / ParkReasons / RejectReasons /
# DoneReasons tables) and internal/stage/liveness.go (AllStates) - and reconcile
# by hand; these are closed sets, not samples.

## state
# tatara-operator v2.0.0, api/v1alpha1/task_types.go:203-219 and
# internal/stage/liveness.go:AllStates - the 8-member Task state enum, in
# lifecycle order. It replaced the 16-stage F.1 enum wholesale (#521).
#
# `parked` and `failed` ARE DELIBERATELY ABSENT and must not be re-added. Park is
# an orthogonal FLAG (status.parkReason, the parkReason section below), liveness
# is a property (stage.Live), and TaskDone is EXACTLY {done, rejected} - folding
# all three axes into one value is the bug #521 fixed.
#
# NAMING TRAP, verbatim from the enum's own doc comment: `merged` and `deployed`
# name the PHASE, not the milestone. merged means the verdict is approve and the
# operator owns the merge cursor, NOT that every MR is merged.
#
# The three LIVE (pod-bearing) states are refined, under-implementation and
# awaiting-review (internal/stage/liveness.go:18-21). merged and deployed are
# operator-driven. new is the operator's own triage pass.
new
refined
under-implementation
awaiting-review
merged
deployed
done
rejected

## stageReason
# RETIRED by tatara-operator v2.0.0 (#521): the label no longer exists on any
# metric. The section is kept, deliberately EMPTY, so that any expression still
# selecting a stageReason value fails CI loudly instead of being waved through by
# an absent section. Its members moved to parkReason and stateReason above.
#
# THE NEGATIVE-MATCHER TRAP THIS SECTION EXISTS TO CATCH (#97): a POSITIVE matcher
# on a dead label selects nothing and reports OK forever, but a NEGATIVE one
# (stageReason!~"a|b") matches EVERY series, because a series with no stageReason
# label trivially satisfies it. "Operator task park spike" spent 2026-08-08 firing
# on the benign parks its own summary said it excluded, for exactly that reason.
# Audit every negative matcher separately after any label rename.

## kind:exempt-metrics
# `kind` is an OVERLOADED label name. On the Task family it is the A.4 origin kind
# (the closed set above); on the metrics below it means something else entirely, so
# the closed-set sweep must not be applied to them. The default is to CHECK: a new
# metric that overloads `kind` fails CI until someone lands it here deliberately.
# Each entry names what its `kind` label actually carries, verified in the operator
# worktree's internal/obs.
#
# scm_metrics.go: kind = the ACCESS CLASS of an SCM call ("write"|"read"), which is
# how dashboards/operator.json splits the write path out of the SCM counter.
operator_scm_writes_total
# operator_metrics.go: kind = the reconciled CR kind (Task|Project|Repository|...).
operator_reconcile_total
# contract K.1: kind = the CR kind whose etcd object is being sized / rejected /
# spilled / adopted, not the Task's origin kind.
operator_object_size_bytes
operator_object_too_large_total
operator_comment_spill_total
operator_orphan_adopted_total
# objbudget_metrics.go: kind = the guarded CR kind being written, exactly
# Issue|MergeRequest|Task (objbudget.go's per-Fit* `const kind`). Same family as
# operator_object_too_large_total above, same reason.
operator_objbudget_spill_blocked_total
# mirror_metrics.go: kind = the mirror WRITE TARGET, and it is not even a clean CR
# kind - the comment_append site passes resolveMirrorTarget's runtime value, so the
# live set is Issue|MergeRequest|issue_comment|mr_comment|mr_review. Never an A.4
# Task kind.
operator_mirror_write_dropped_total
